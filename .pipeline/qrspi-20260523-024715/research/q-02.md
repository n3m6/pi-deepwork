# Q2: Subagent Dispatch Mechanics, Return Contracts, Telemetry, and Git Integration

## Summary

The deepwork orchestrator dispatches each of 10 stages to dedicated subagents using `Invoke <agent> as a subagent` patterns with structured prompt headers, parses a fixed return contract of `###`-delimited sections, emits structured JSONL telemetry events at every boundary, regenerates a `run-log.md` timeline, generates `metrics-summary.md` at completion/abort, and creates git commits at every stage boundary. The telemetry event schema is formalized in `protocol/telemetry-protocol.md`.

## 2. Return Contract Headers Parsed and Logic Triggered

Defined at `deepwork.md:132-144`:

| Header | Stages that return it | Logic triggered |
|---|---|---|
| `### Status` | All stages | `PASS` → proceed to next stage; `FAIL` → **Error Handling** (`deepwork.md:900-912`). Verify additionally returns `PARTIAL` or `FAIL` (Stage 9 handler, `deepwork.md:847-864`). |
| `### Files Written` | All stages | Used as the `artifacts` payload in `stage.completed` / `stage.failed` telemetry events. |
| `### Route` | Stage 1 (Goals) only | Stores `full` or `quick-fix` in context; determines whether Stages 4, 5, and Replan are skipped (`deepwork.md:544`). Locked after Stage 6 (`deepwork.md:690`). |
| `### Phase` | Stage 7, 8, 8.5 | Indicates the current phase number from implement/accept/replan (referenced but not directly parsed by deepwork — phase context is maintained in `state.md`). |
| `### Backward Loop Request` | Stage 7, 8, 8.5 | If present, **Backward Loop Protocol** is invoked instead of normal stage completion (`deepwork.md:727, 766, 811`). |
| `### Summary` | All stages | Used for telemetry `summary` field and displayed to user in Error Handling responses. |
| `### Telemetry` | All stages (optional) | Single-line JSON parsed as `context` payload for telemetry events (`deepwork.md:144`). Absence is never an error. Contains stage-specific metrics. |
| `### Report Content` | Stage 10 | Parsed from Stage 10 return and presented to user verbatim (`deepwork.md:879`). |

Additional cross-check logic:
- **Allowed-list cross-check (Rule 11):** After Stages 8, 8.5, 9, and 10, deepwork runs `git diff --stat` between the prior stage-boundary checkpoint and HEAD, parses changed paths, and compares against allowed globs (`deepwork.md:64-66`). Contract violations trigger Error Handling.
- **Stage 6 unclean-cap gate:** If `### Telemetry.terminal_review_state` is `unclean-cap` or `stable-cap`, deepwork pauses via `question` with options A-D (`deepwork.md:669-678`).
- **Stage 8.5 unclean-cap gate:** Same pattern, parsed from `### Telemetry`, with options A-D (`deepwork.md:813-822`).
- **Stage 9 auto-fix route:** On `### Status — FAIL`, deepwork parses `stage9-summary.md` for failing evidence and dispatches `qrspi-implement` in `verify-fix` mode (`deepwork.md:850-858`).

## 3. Telemetry Event Schema (All Event Types)

Defined in `protocol/telemetry-protocol.md` lines 41-80. Every event has required envelope fields:

**Required envelope fields (all events):** `telemetry-protocol.md:44`
- `schema_version: "1"`
- `event_id: "<run-id>-<seq>"`
- `sequence: <int >= 1>`
- `ts: <YYYY-MM-DDTHH:MM:SSZ UTC>`
- `run_id: "qrspi-YYYYMMDD-HHMMSS"`
- `writer_agent: <name>`
- `writer_scope: "controller" | "stage-orchestrator" | "nested-orchestrator"`
- `event_type: <see taxonomy below>`
- `status: "info" | "pass" | "fail" | "skip" | "warn"`
- `route: "full" | "quick-fix" | "unknown"`
- `summary: <one sentence>`

**Conditional scope fields:** `telemetry-protocol.md:46`
- `stage` — all non-`run.*` events
- `stage_instance: <int>` — starts at 1, increments on retry/resume/backward-loop re-entry
- `phase: <int>` — stages 7/8/8.5
- `wave: <int>` — stage 7 waves
- `task_id` — task-scoped
- `review_round: <int>` — review-loop events
- `attempt: <int>` — retry events
- `child_agent` + `correlation_id` — all `child.*` events
- `parent_event_id` — `child.returned` only

**Payload objects (omit when empty):** `telemetry-protocol.md:48`
- `context: {...}` — stage metrics from `### Telemetry` return
- `artifacts: [...]` — relative file paths
- `timing: {started_at, ended_at, duration_s}`
- `decision: {choice, reason}` — gate and loop events
- `error: {message, artifact}` — fail events
- `git: {commit, message}` — checkpoint events

**Event Taxonomy:** `telemetry-protocol.md:52-65`

| Event Type | Statuses | Writer |
|---|---|---|
| `run.started` | info | deepwork |
| `run.resumed` | info | deepwork |
| `run.completed` | pass / warn / fail | deepwork |
| `run.aborted` | fail | deepwork |
| `stage.started` | info | deepwork |
| `stage.completed` | pass / warn | deepwork |
| `stage.failed` | fail | deepwork |
| `stage.skipped` | skip | deepwork |
| `stage.retried` | info | deepwork |
| `phase.started` | info | qrspi-implement |
| `phase.completed` | pass | qrspi-implement |
| `gate.presented` | info | deepwork |
| `gate.approved` | pass | deepwork |
| `gate.rejected` | warn | deepwork |
| `child.dispatched` | info | stage orchestrator |
| `child.returned` | pass / fail | stage orchestrator |
| `review.round_started` | info | stage orchestrator |
| `review.round_completed` | pass / fail | stage orchestrator |
| `backward_loop.requested` | warn | deepwork |
| `backward_loop.decided` | info | deepwork |
| `backward_loop.deferred` | info | deepwork |
| `backward_loop.reset` | warn | deepwork |
| `checkpoint.created` | info | deepwork |
| `artifact.generated` | info | deepwork / any |
| `metrics.generated` | info | deepwork |

**Per-event minimum contracts:** `telemetry-protocol.md:67-81`
- `stage.*`: must include `stage`, `status`, `summary`, `timing`. `stage.completed` may use `status: "warn"` for Verify `PARTIAL`.
- `child.*`: must include `child_agent`, `correlation_id`, `stage`. `child.returned` also includes `parent_event_id`, `artifacts`, `context` with `{"status": "PASS"|"FAIL"}`.
- `gate.*`: must include `stage`. Synthesis rules using `gate_round_details` or `gate_status`/`gate_rounds` for round modeling.
- `backward_loop.*`: must include `stage`, `phase`, `decision` (for `decided`/`deferred`). `backward_loop.decided` requires `context.loop_target`, `context.deleted_artifacts`, `context.archived_artifacts`. Optional: `context.local_fix_override: true`, `context.deferred_remediation: true`.
- `checkpoint.created`: must include `stage`, `git.message`, `git.commit` (short SHA or `"clean-worktree"`).

| Research (3) | `question_count`, `codebase_count`, `web_count`, `hybrid_count`, `review_rounds`, `terminal_review_state` |
| Design (4) | `review_rounds`, `gate_status`, `gate_rounds`, `gate_wait_time_s` (opt), `gate_round_details` (opt), `terminal_review_state` |

**Event emission procedure:** `deepwork.md:156-164`
1. `date -u +%Y-%m-%dT%H:%M:%SZ` to capture UTC timestamp
2. Compose JSON event with `"<run-id>-<telemetry_seq>"` as `event_id` and `telemetry_seq` as `sequence`
3. `cat .pipeline/<run-id>/telemetry/events.jsonl` to read current file
4. Overwrite the file with previous content plus new JSON line appended (no trailing blank lines)
5. Increment `telemetry_seq`

**Sequence counter initialization:** `deepwork.md:152`
- Fresh run: `telemetry_seq = 1`
- Resume: count lines in `events.jsonl`, set `telemetry_seq = count + 1`

## 4. `run-log.md` Regeneration Template

Defined at `deepwork.md:168-226`. Six sections:

```markdown
# Run Log — <run-id>

## Run Overview
- **Run ID:** <run-id>
- **Route:** full | quick-fix | unknown
- **Status:** in-progress | completed | aborted
- **Started:** <ts of run.started>
- **Completed / Aborted:** <ts> or —
- **Resume count:** <N> (0 for fresh run)
- **Stages completed:** goals, questions, ... (from events)
- **Next stage:** <stage> or done

## Current Status
<one-line signal, e.g. "Stage 7 — Implement — Phase 2 complete. Next: Accept-Test.">

## Timeline
| Time (UTC) | Seq | Scope | Event | Status | Summary | Artifacts |

## Active Phase Snapshot
- **Current phase:** X of N
- **Current stage:** <stage>
- **Waves completed:** X of N
- **Acceptance state:** pending
- **Outstanding blockers:** none

## Failure and Loop Index
| Type | Stage | Phase | Round | Summary | Artifact |

## Artifact Index
- `state.md` — current recovery state
- `config.md` — route and metadata
- `goals.md` — distilled intent
- `plan.md` — current plan
- `phase-manifest.md` — phase breakdown
- `telemetry/events.jsonl` — full event stream
```

**Regeneration triggers:** After each stage boundary, after backward-loop decisions, and on abort/resume (`deepwork.md:168`).

## 5. `metrics-summary.md` Structure

Defined at `deepwork.md:228-306`. Generated at Stage 10 completion and on run abort. Eight sections:

- **Run** — Route, Final status, Total duration, Stages completed, Resume count, Backward loop count
- **Stage Durations** — Per stage per phase duration and status table
- **Child Agent Calls** — Per stage child agent call counts, pass/fail rates
- **Review Rounds** — Per stage per type review round counts
- **Retry and Loop Counts** — Stage retries, E2E/regression/acceptance remediation rounds, backward loop decision breakdowns
- **Human Gate Outcomes** — Per stage presentations/rejections/approvals
- **Test Evidence Quality** — Per phase evidence classification counts (Deterministic/Flaky/Harness Noisy/Ambiguous/Redundant/No-Test Tasks/Overrides)
- **Code Health** — Simplifier findings, coverage status, Plan/Replan terminal review states

After writing, emit a `metrics.generated` event (`deepwork.md:229`).

## 6. Git Commands and Commit Messages at Stage Boundaries and Pre-Flight

**Git availability detection logic:** The file does not contain explicit `git --version` or `which git` detection commands. Git is assumed available — the permission block explicitly allows `git status`, `git add`, `git commit`, `git checkout` (`deepwork.md:17-20`). The file only specifies running git when the pipeline is active.

**Pre-Flight git:** `deepwork.md:495`
- `git checkout -b qrspi/<run-id> main` — creates a new branch from `main`

**Stage boundary checkpoint procedure (Rule 8):** `deepwork.md:52`
- After each successful stage completion or quick-fix skip, once `state.md` reflects the new stage boundary:
  1. `git status --short` — check if worktree is dirty
  2. If dirty: `git add -A` and `git commit -m "qrspi: stage <N> <name> <complete|skipped>"`
  3. If clean: skip commit without error
