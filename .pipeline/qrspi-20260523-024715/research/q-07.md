# Q7: Pi Extension UI Methods — ctx.ui.confirm(), ctx.ui.select()

## Summary
Pi's extension runtime exposes interactive UI methods through `ctx.ui`, accessible within any event handler, tool execution, or command handler that receives an `ExtensionContext`. The two key dialog methods are `ctx.ui.confirm()` (returns `Promise<boolean>`) and `ctx.ui.select()` (returns `Promise<string | undefined>`). Both support a `timeout` option (milliseconds) for auto-dismissal with live countdown, and an `AbortSignal` option for manual dismissal control.

## `ctx.ui.confirm()` — Parameter Shape and Return Type

```typescript
ctx.ui.confirm(title: string, message: string, options?: { timeout?: number; signal?: AbortSignal }): Promise<boolean>
```
- **Parameters:**
  - `title` (string, positional): The dialog title / header
  - `message` (string, positional): The body text asking the question
  - `options` (optional object):
    - `timeout` (number): milliseconds before auto-dismiss with live countdown ("Title (5s)" → "Title (4s)" → …)
    - `signal` (AbortSignal): for manual dismissal control; aborted signal → dialog dismissed
- **Return type:** `Promise<boolean>`
  - `true` — user confirmed / selected "Yes"
  - `false` — user cancelled (Escape or "No"), OR timed out

## `ctx.ui.select()` — Parameter Shape and Return Type

```typescript
ctx.ui.select(title: string, options: string[], opts?: { timeout?: number; signal?: AbortSignal }): Promise<string | undefined>
```
- **Parameters:**
  - `title` (string, positional): The dialog title / header
  - `options` (string[], positional): Array of string choices
  - `opts` (optional object): Same timeout/signal as `confirm()`
- **Return type:** `Promise<string | undefined>`
  - Returns the selected option string if user picks one
  - Returns `undefined` if user cancels OR on timeout

## Other Interactive UI Methods on `ctx.ui`

| Method | Signature | Return | Description |
|---|---|---|---|
| `input(title, placeholder, opts?)` | `(string, string, { timeout?, signal? }?)` | `Promise<string \| undefined>` | Single-line text input |
| `editor(title, prefilledText, opts?)` | `(string, string, { timeout?, signal? }?)` | `Promise<string \| undefined>` | Multi-line editor |
| `notify(message, level)` | `(string, "info" \| "warning" \| "error")` | `void` | Non-blocking notification |
| `setStatus(key, text?)` | `(string, string?)` | `void` | Footer status line |
| `setWidget(key, content, opts?)` | `(string, any, any?)` | `void` | Widget above/below editor |
| `setTitle(title)` | `(string)` | `void` | Terminal title |
| `custom(component, props?)` | `(Component, any?)` | `Promise<any>` | Full TUI component |

## Lifecycle Constraints on When `ctx.ui` Can Be Called

1. **Available in all event handler contexts**: Any handler receiving `ExtensionContext` — including `session_start`, `tool_call`, `tool_result`, `input`, `before_agent_start`, commands, shortcuts, and tool executions.
2. **Print/JSON mode is unavailable**: `ctx.hasUI` is `false` in print mode (`-p`) and JSON mode. `true` in interactive and RPC mode.
3. **RPC mode**: Dialog methods work via the extension UI sub-protocol. Fire-and-forget methods (`notify`, `setStatus`, `setWidget`) emit requests to the client.
4. **No explicit "tool execution only" constraint**: Available in session events, commands, shortcuts, and tool callbacks alike. The only limitation is mode-based.
5. **Timed dialog behavior**: `confirm()` returns `false` on timeout; `select()` returns `undefined` on timeout; `input()` returns `undefined` on timeout. Use `AbortSignal` to distinguish timeout from user cancel.
