# Q4: Pi Extension System — Commands, Tools, Skills, and Lifecycle

## Summary
Pi's extension system uses a factory-function lifecycle (analogous to `activate(ctx)`), where extensions receive an `ExtensionAPI` object that provides event subscriptions, tool/command registration, UI primitives, and lifecycle hooks. The `resources_discover` event enables extensions to inject additional skill, prompt, and theme paths. Pi's native skill loader discovers skills from `<root>/<name>.md` (flat file) and `<root>/.../<name>/SKILL.md` (directory skill, recursively).

## Extension Lifecycle (activate/deactivate)
Pi extensions export a **default factory function** that receives `ExtensionAPI`:
```typescript
export default function (pi: ExtensionAPI) { /* ... */ }
```
The factory can be async; pi awaits async factories before startup continues. For cleanup, extensions subscribe to `session_shutdown`:
```typescript
pi.on("session_shutdown", async (event, ctx) => {
  // event.reason - "quit" | "reload" | "new" | "resume" | "fork"
});
```

- Source: `https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/extensions/types.ts`

## ExtensionContext Shape
```typescript
interface ExtensionContext {
  ui: ExtensionUIContext;
  hasUI: boolean;                   // false in print/RPC mode
  cwd: string;
  sessionManager: ReadonlySessionManager;
  modelRegistry: ModelRegistry;
  model: Model<any> | undefined;
  isIdle(): boolean;
  signal: AbortSignal | undefined;
  abort(): void;
  hasPendingMessages(): boolean;
  shutdown(): void;
  getContextUsage(): ContextUsage | undefined;
  compact(options?: CompactOptions): void;
  getSystemPrompt(): string;
}
```

**Command handlers** receive `ExtensionCommandContext`, which extends `ExtensionContext` with `waitForIdle()`, `newSession()`, `fork()`, `navigateTree()`, `switchSession()`, and `reload()`.

## ExtensionAPI — Event Subscription
Events subscribed via `pi.on(eventName, handler)`. Key events:

| Event | When Fired |
|-------|-----------|
| `resources_discover` | After `session_start`; extensions contribute additional resource paths |
| `session_start` / `session_shutdown` | Session lifecycle |
| `before_agent_start` | After prompt submission, before agent loop |
| `agent_start` / `agent_end` | Agent loop boundaries |
| `turn_start` / `turn_end` | Each LLM+tool-call cycle |
| `tool_call` / `tool_result` | Tool lifecycle; can block or mutate |
| `input` | User input received; can intercept/transform |
| `model_select` / `thinking_level_select` | Model/thinking changes |

## Tool Registration
Tools registered via `pi.registerTool(definition)`:
```typescript
interface ToolDefinition<TParams extends TSchema = TSchema> {
  name: string;
  label: string;
  description: string;
  promptSnippet?: string;
  promptGuidelines?: string[];
  parameters: TParams;  // TypeBox schema
  renderShell?: "default" | "self";
  prepareArguments?: (args: unknown) => Static<TParams>;
  executionMode?: ToolExecutionMode;
  execute(
    toolCallId: string,
    params: Static<TParams>,
    signal: AbortSignal | undefined,
    onUpdate: AgentToolUpdateCallback | undefined,
    ctx: ExtensionContext,
  ): Promise<AgentToolResult>;
}
```
The `execute` function returns `{ content: TextContent[], details?: TDetails }`. Tools from pi-supervisor use `defineTool()` + TypeBox schemas.

## resources_discover Event Shape
```typescript
interface ResourcesDiscoverEvent {
  type: "resources_discover";
  cwd: string;
  reason: "startup" | "reload";
}
interface ResourcesDiscoverResult {
  skillPaths?: string[];
  promptPaths?: string[];
  themePaths?: string[];
}
```
Extensions return `ResourcesDiscoverResult` to inject paths.

## Skill Discovery Convention — `skills/<name>/SKILL.md`
Pi's native skill loader discovers skills from:
1. `~/.pi/agent/skills/` (global, Pi standard)
2. `~/.agents/skills/` (global, Agent Skills spec)
3. `<cwd>/.pi/skills/` (project, Pi standard)
4. `<cwd>/.agents/skills/` (project, Agent Skills spec)

Discovery rules:
- Flat-file skills (only in `~/.pi/agent/skills/` and `.pi/skills/`): `<root>/<name>.md`
- Directory skills (all locations): `<root>/.../<name>/SKILL.md` — discovered recursively. If a directory contains `SKILL.md`, it is treated as a skill root and recursion stops. `node_modules` and dotfile directories are skipped.

The `SKILL.md` file uses YAML frontmatter with required `name` and `description` fields.

Additionally, pi-subagents implements its own skill preloader (`skill-loader.ts`) following the same convention with these discovery roots (first match wins):
1. `<cwd>/.pi/skills/` (project)
2. `<cwd>/.agents/skills/` (project)
3. `$PI_CODING_AGENT_DIR/skills/` (user)
4. `~/.agents/skills/` (user)
5. `~/.pi/skills/` (legacy)

Symlinks are rejected by pi-subagents for security.
