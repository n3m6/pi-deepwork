# Q8: Pi Extension Discovery and Installation — Directories, pi install, npm-symlink

## Summary
Pi auto-discovers extensions from `~/.pi/agent/extensions/` (global) and `.pi/extensions/` (project-local). The `pi install` command supports `npm:` and `git:` sources with `@ref` syntax for branch/tag/commit pinning. Git clones are full clones (no `--depth`). No explicit npm-symlink mechanism is used for extension registration — pi discovers `.ts` files by scanning the filesystem.

## Extension Discovery Directories

Pi auto-discovers extensions from:
- `~/.pi/agent/extensions/*.ts` (global, all projects)
- `~/.pi/agent/extensions/*/index.ts` (global, subdirectory with index)
- `.pi/extensions/*.ts` (project-local)
- `.pi/extensions/*/index.ts` (project-local, subdirectory)

Additional paths via `settings.json` under `"extensions"` array. The `PI_CODING_AGENT_DIR` env var overrides the default config directory (`~/.pi/agent`).
- Source: `packages/coding-agent/docs/extensions.md`; `packages/coding-agent/README.md`

## Expected Extension Structure — `package.json` and Entry Point

For **directory-based** extensions, pi looks for:
1. `package.json` with `"pi": { "extensions": ["./src/index.ts"] }` — resolves listed paths
2. If no `pi` manifest: `index.ts` or `index.js` in directory root
3. Otherwise: scans for `.ts`/`.js` files in the directory

For **pi packages** (distributed via npm/git), the `package.json` must contain:
```json
{
  "name": "my-package",
  "keywords": ["pi-package"],
  "pi": {
    "extensions": ["./extensions"],
    "skills": ["./skills"],
    "prompts": ["./prompts"],
    "themes": ["./themes"]
  }
}
```
Without the `pi` manifest, pi auto-discovers from conventional directories: `extensions/`, `skills/`, `prompts/`, `themes/`.
- Source: `packages/coding-agent/docs/packages.md`; `packages/coding-agent/README.md`

The **extension TypeScript entry** exports a default factory function:
```typescript
export default function (pi: ExtensionAPI) { ... }
```
Loaded via [jiti](https://github.com/unjs/jiti), so TypeScript works without compilation.
- Source: `packages/coding-agent/docs/extensions.md`

## `pi install` CLI — Git URL Resolution (Branch/Tag Syntax)

Supported source formats:
```bash
pi install npm:@foo/bar              # latest
pi install npm:@foo/bar@1.2.3        # pinned version
pi install git:github.com/user/repo
pi install git:github.com/user/repo@v1   # tag/branch/commit ref
pi install git:git@github.com:user/repo
pi install git:git@github.com:user/repo@v1
pi install https://github.com/user/repo
pi install https://github.com/user/repo@v1
pi install ssh://git@github.com/user/repo
pi install ssh://git@github.com/user/repo@v1
```
- Source: README `packages/coding-agent/README.md`; `packages/coding-agent/docs/packages.md`

**Branch/tag resolution** handled by `parseGitUrl()` in `packages/coding-agent/src/utils/git.ts`:
- The `@` character separates the repo URL from the ref
- Refs can be tag, branch name, or commit SHA
- Refs are **pinned**: `pi update` and `pi update --extensions` do not move pinned git refs

## Git Clone Behavior (No Shallow Clone)

The `installGit()` method performs a **full clone**:
```typescript
await this.runCommand("git", ["clone", source.repo, targetDir]);
if (source.ref) {
    await this.runCommand("git", ["checkout", source.ref], { cwd: targetDir });
}
```
There is **no `--depth 1` or shallow-clone flag**. After cloning, if `package.json` exists, pi runs `npm install --omit=dev` in the target directory.

**Install paths:**
- Git packages (global): `~/.pi/agent/git/<host>/<path>`
- Git packages (project): `.pi/git/<host>/<path>`
- npm packages (global): `~/.pi/agent/npm/`
- npm packages (project): `.pi/npm/`

## npm Symlink-based Installation Pathway

Pi does **not use symlinks** for extension discovery. The mechanism is filesystem-based scanning:
1. **npm packages**: installed with `npm install <spec> --prefix <root>` into the npm root directory.
2. **git packages**: cloned to a filesystem directory, then `npm install --omit=dev` run if `package.json` exists.
3. **Local extensions**: placed directly as `.ts` files in `~/.pi/agent/extensions/` or `.pi/extensions/`. Discovered by scanning the filesystem.

For **ad-hoc development** without installing, use `pi -e <path>`:
```bash
pi -e npm:@foo/bar                # temporary npm install
pi -e git:github.com/user/repo    # temporary git clone
pi -e ~/projects/my-ext/src/index.ts  # direct file path
```
