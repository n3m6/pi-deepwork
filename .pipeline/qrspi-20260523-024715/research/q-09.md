# Q9: pi-subagents Presence/Absence Signaling at Runtime

## Summary

The npm package is **`@tintinweb/pi-subagents`** (v0.7.3). The extension signals its runtime presence through two mechanisms: (1) setting `Symbol.for("pi-subagents:manager")` on `globalThis` synchronously during extension init, and (2) emitting a `subagents:ready` event on the `pi.events` event bus. No explicit failover or graceful-degradation protocol for the "not installed" case is documented; both mechanisms return nothing when the extension is absent, leaving detection entirely up to the consumer.

## npm Package Identifier

- **Exact name:** `@tintinweb/pi-subagents`
- **Current version:** `0.7.3`
- **Source:** `package.json`; npm listing: `https://www.npmjs.com/package/@tintinweb/pi-subagents`

## Runtime Signaling Mechanism #1: `Symbol.for("pi-subagents:manager")` on `globalThis`

- **When set:** Synchronously at extension-init time — in the top-level body of the `export default function (pi)` handler, before any tool or command registrations.
- **What is set:** A lightweight facade object with four methods: `waitForAll()`, `hasRunning()`, `spawn()`, `getRecord()`.
- **Exact code** (`src/index.ts`, lines ~431–440):
  ```ts
  const MANAGER_KEY = Symbol.for("pi-subagents:manager");
  (globalThis as any)[MANAGER_KEY] = {
    waitForAll: () => manager.waitForAll(),
    hasRunning: () => manager.hasRunning(),
    spawn: (piRef: any, ctx: any, type: string, prompt: string, options: any) =>
      manager.spawn(piRef, ctx, type, prompt, options),
    getRecord: (id: string) => manager.getRecord(id),
  };
  ```
- **When cleaned up:** On `session_shutdown`, the key is deleted: `delete (globalThis as any)[MANAGER_KEY];`
- **Source:** `https://raw.githubusercontent.com/tintinweb/pi-subagents/master/src/index.ts` — lines 431–440 (set) and line 495 (delete)

## Runtime Signaling Mechanism #2: `pi.events.emit("subagents:ready")`

- **When emitted:** After RPC handlers are registered, inside the same init function. Expected consumer pattern:
  ```js
  pi.events.on("subagents:ready", () => {
    // RPC handlers are registered — safe to call ping/spawn/stop
  });
  ```
- **Source:** README section "Cross-Extension RPC → Discovery"; `src/index.ts` line ~487

## Module Resolution Behavior When NOT Installed

Since `@tintinweb/pi-subagents` is a **pi extension** (loaded via `pi install` or `pi -e`), it is never `require()`'d or `import {} from`'d by consumers in the traditional Node.js sense. Two access patterns exist, neither throws when absent:

1. **Symbol-based access:** `(globalThis as any)[Symbol.for("pi-subagents:manager")]` — evaluates to `undefined` when extension not loaded. No error thrown. Consumer must null-check.
2. **Event-based RPC access:** `pi.events.emit("subagents:rpc:ping", { requestId })` — when extension not loaded, no handler replies. Caller experiences timeout or never receives response. No error thrown.
3. **`subagents:ready` event:** Simply never fires when extension absent.

The package has **no** `main` or `exports` fields consumed via `require()`/`import`. Its only entry point is the pi extension entry `"./src/index.ts"` under `"pi.extensions"` in `package.json`.

## Graceful Degradation Patterns (Documented/Observed)

**No formal protocol** for graceful degradation when absent is documented in README, CHANGELOG, or source code. The extension provides building blocks:

- **Symbol check:** `const hasSubagents = !!(globalThis as any)[Symbol.for("pi-subagents:manager")];`
- **Event listener pattern:** Listen for `subagents:ready` with timeout; fall back to user message if event never fires
- **Ping pattern (RPC):** Use RPC ping with `requestId` and timeout; lack of reply signals absence

The test suite does not test "extension not present" scenarios. The CHANGELOG v0.5.0 entry notes cross-extension RPC as the intended detection surface.
